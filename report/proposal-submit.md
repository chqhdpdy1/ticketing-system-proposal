# Term Project Proposal — Ticketing System

> 국민대학교 · Software Architecture · HW1 Project Proposal
> 설계 v2.0 반영본 / 2026-10-31 / 구현 전 계획

## 1. 프로젝트 팀 명

**Ticketing System**

## 2. 프로젝트 주제

**공용 선착순 판매 코어와 영화관 티켓 예매 시스템**

같은 좌석을 여러 사람이 동시에 선택하거나 판매 시작 순간 접속이 몰리는 상황을 처리한다. 공통 판매 기능과 영화관 정보를 분리해 다른 지정 단위 판매에도 재사용할 수 있는 구조를 목표로 한다. 모든 판매 분야를 수정 없이 지원한다고 미리 보장하지는 않는다.

## 4. 시스템 목표 (Vision & Scope)

**목표:** 하나의 좌석을 중복 판매하지 않고, 결제하지 않은 좌석을 다시 판매할 수 있게 한다. 접수 순서대로 구매를 시도할 권한을 주되, 실제 좌석 확보·결제 완료 순서는 보장하지 않는다.

**이번 범위:** 한 번에 한 좌석 예매, 대기줄, 선점·해제·시간 만료, 주문, 가짜 결제, 티켓 발급·조회, 간단한 로그인, 관리자 상영 등록.

**제외:** 실제 결제·문자, 결제 후 취소·환불, 여러 좌석 동시 예매, 수량 상품, 추천·정산, 모바일 전용 앱.

| 비교 | 단순 구현 | 이번 설계 |
|---|---|---|
| 좌석 확보 | 확인과 변경이 분리되어 중복 가능 | DB에서 잠금과 거래로 함께 처리 |
| 선점 만료 | 프로그램 종료 시 놓칠 수 있음 | DB의 만료시각을 다시 확인해 처리 |
| 접속 집중 | 모든 요청이 구매 기능에 바로 도달 | 대기줄로 신규 구매 시도 제한 |
| 구조 | 상영 정보와 판매 기능 결합 | 판매 코어와 영화관 모듈 분리 |

비교 대상은 특정 상용 서비스가 아니라 동시성 제어 없는 단순 구현이다.

## 5. 시스템 개요 및 특성

한 서버 프로그램 안에서 역할별 모듈을 나눈다. PostgreSQL이 좌석·주문·결제의 기준 정보를 보관하고, Redis는 대기줄을 관리한다. 가짜 결제 성공과 좌석 판매·티켓 발급을 하나의 DB 거래로 처리한다.

| 기능 | 정보·책임 | 필요한 동작 | 설계 원칙 | 품질 목표 |
|---|---|---|---|---|
| 판매 조회 | 상영·좌석 | 목록·상세·좌석맵 | Layered / Information Expert / Repository | 빠른 조회 |
| 대기줄 | 사용자·순번·입장권 | 중복 접수 방지·순차 입장 | Ports & Adapters / Controller | 접수 순서 |
| 자리 잡기 | 좌석·소유자·만료시각 | 한 좌석 선점·해제·만료 | SRP / DB 트랜잭션 | 중복 선점 0 |
| 주문·결제 | 주문·금액·가짜 결제 | 본인 확인·중복 처리 방지·확정 | Adapter / Application Service | 중복 판매 0 |
| 티켓 발급 | 주문·티켓 코드 | 결제와 함께 발급·본인 조회 | Creator / UNIQUE 제약 | 발권 누락 0 |
| 판매 등록 | 상영·회차별 좌석 | 관리자 등록·가격 설정 | Layered / Repository | 권한·정보 일치 |
| 미결제 취소 | 선점·주문 상태 | 자리 반환·주문 종료 | 조건부 상태 전이 | 중복 반환 0 |

**검증 가능한 목표:**

- 같은 좌석에 동시 1,000개 요청이 와도 유효한 선점은 최대 1개.
- 정상 동작 중 만료 후 5초 이내 재판매 가능을 목표로 측정.
- 명시된 허용 부하에서 조회 p95 300ms 미만, 선점 p95 500ms 미만 목표. 대기줄 대기시간은 별도 기록.
- 예상하지 않은 서버 오류율 1% 미만 목표. 매진·충돌·요청 제한 비율도 따로 공개.
- 두 번째 지정 단위 판매를 연결하며 코어 변경량을 측정.

위 수치는 아직 실행하지 않은 목표이며 결과를 보장하는 표현이 아니다.

## 6. 사용 기술 및 Framework

| 구분 | 기술 | 이유 |
|---|---|---|
| 서버 | Java 17 + Spring Boot 3 | 거래 처리·역할별 모듈 구성 |
| 데이터 | PostgreSQL + JPA + Flyway | 잠금·제약·변경 이력 관리 |
| 대기줄 | Redis | 순번·입장 상태 관리 |
| 화면 | React + Vite + TypeScript | 예매 흐름 표시 |
| 검증 | JUnit5 + Testcontainers + k6 | 실제 DB·동시 요청·장애 시험 |
| 실행 | Docker Compose | 실행 조건 재현 |

가상 대기실 개념을 참고하되 특정 예매 업체의 내부 구현을 확인한 것으로 주장하지 않는다. Redis 재고와 DB 후행 저장은 초기 구현에서 사용하지 않는다.
